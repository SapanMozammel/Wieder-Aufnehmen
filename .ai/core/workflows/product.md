# Product discovery

Read the current task, project profile and roles. Start from a concrete user
problem and the situation in which it occurs. Separate observations, assumptions
and proposed solutions. Use interviews, existing support evidence or bounded
research when available; do not invent user quotes or market validation.

Create a product brief: target users, job to be done, current alternatives,
measurable outcome, friction, commercial constraints, dependencies, excluded
scope and a smallest useful release. Define what evidence would change direction.
Estimate operating cost and support burden as well as implementation cost.

Prioritize one complete user journey before feature breadth. Explain tradeoffs
in plain language, including accessibility, privacy and failure recovery. A claim
such as “best” needs a specific comparative outcome and a test. Give design and
engineering observable acceptance criteria before implementation.
