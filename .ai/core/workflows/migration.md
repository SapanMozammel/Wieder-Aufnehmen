# Migration and adoption

Inventory existing instructions, commands, ownership and protected behavior.
Read external guidance before adopting it; record source/version/digest and
license status. Preserve the project's higher-priority policies.

Create a preview listing creates, updates, preserved files and conflicts. Review
the exact target root and content changes. Never bulk-sync vendor directories,
overwrite unknown instructions, follow symlinks, execute discovered scripts, or
change global settings. Resolve conflicts manually into project-owned guidance.

Apply only the reviewed plan against unchanged inputs. Verify installed hashes,
project context and a representative handoff. Record old/new versions and an
explicit rollback route. For data migrations, separately plan backup, validation,
rollout and recovery within user authority. Ejection must preserve tasks,
decisions and local edits and remove dangling discovery links through review.
